### v4.31で追加した固定チェック

- `R-12【費用感】` の見出しだけでなく、候補の採否・順位・A/C/Eの順序や時期への不使用、負担割合等の前提明示、欠測時の「要確認」、施設の月額総額構造、償還払い、施行時点確認、利用量創作禁止等の実質条項が全AI経路から脱落しないこと
- `R-11 → R-12 → 第2部`、`S5 → S5.5 → S6`、`B → B-費用 → C` の順序が維持されること
- 1割を暗黙に前提とする概算、`1単位＝10円` での概算、一律の割合加算、費用による順位変更、数字を示せない候補の省略等の危険な逆指示が相談文へ混入しないこと
- 費用構造を確認できない場合に `費用構造：要確認` とできること
- 利用者が追加質問で利用量や負担割合を示した場合は「利用者が示した仮定」として扱い、AI側から条件を補完しないこと
- Bの候補について、費用が生じないことを公式本文で確認できたものを除きB-費用でも扱うこと

これらはAI回答の金額そのものを正しいと保証するテストではなく、生成される相談文の安全仕様、順序、禁止事項が意図しない改修で崩れていないことを検出する回帰テストである。実際の費用回答は架空症例による別途評価を行う。

## 実行方法

```bash
npm install        # 初回のみ（jsdom を取得）
npm test           # 全テスト（ランダム架空症例600回を含む。約40秒）
npm run test:quick # ランダム100回の短縮版
```

別のファイルや乱数シードを指定する場合：

```bash
node tests/regression.test.js path/to/index.html --random 600 --seed 20260928 --verbose
```

成功時は `結果: すべて成功`（終了コード0）、失敗時は失敗した入力の組み合わせと理由を表示し、
`結果: 失敗 N件 — リリースしないでください`（終了コード1）で終わります。
ランダム症例の失敗は `#番号（seed=…）` が表示されるので、同じ seed で再実行すれば同じ症例を再現できます。

## 検査内容

| 区分 | 内容 |
|---|---|
| 起動 | 読み込み時の例外、利用条件への同意後に入力欄が有効になるか |
| 全組み合わせ | 入力担当者×希望する使い方×本人の希望（現行150通り。選択肢はHTMLから自動取得）で生成。例外、相談メモ、AI経路の相談文が末尾まで生成されるか、`undefined`・`${`等の混入、読者／0-B／R-7／A節1点目／自己監査⑦の分岐、必須安全文の有無、元の症例条件が区切りの内側に丸ごと入っているか。v4.30.1以降はR-9～R-11も固定検査し、候補化前の除外・制限条件確認、強い行動断定の公式根拠、推定禁止と探索継続の分離が相談文から脱落していないかを確認する |
| 本人意向 | 家族・職員＋意向未確認、本人＋情報だけ／支援不要、本人＋職員経路（旧M2） |
| 整合性 | 確認欄なしで停止するか、指摘が相談文へ渡るか、指摘なしで「なし」になるか |
| ゲート | 目視確認なし・市区町村なしで停止、一般的な補足文で誤停止しないか、個人情報らしき記載で停止するか |
| ランダム | ランダム架空症例を指定回数生成し、全組み合わせと同じ検査＋整合性の指摘が残らないか |
| CSV | 保存→別ページで読込→呼び出し→再生成で、全項目と相談文が一致するか、数式インジェクション対策、無関係なCSVの拒否 |
| ボタン | コピー、txtダウンロード、印刷、入力変更時に古い相談文が消えるか |

## プロンプト文言を意図的に変えたとき

期待値はテストファイル冒頭の `SPEC` に仕様として固定しています（実装から読み取りません）。
文言を意図的に変更した場合は `SPEC` の該当文字列も同じコミットで更新してください。
`SPEC` を変えていないのにテストが落ちた場合は、意図しない変更・脱落の可能性があります。

v4.30.1では、R-9～R-11に加えて次の安全仕様も `SPEC` に固定しています。

- R-9：対象要件を確認できても、候補性を左右する対象外・除外・継続利用等の制限条件を公式本文で確認できない場合は、「制限なし」と扱わず「情報不足」の確認候補として残すこと
- 0-A：「情報不足」には、入力欠測だけでなく、候補性を左右する条件を公式本文で確認できない場合も含むこと
- R-10：「必須」「期限」「失権」等の強い断定は適用される公式本文で確認し、全国一律の法定要件は国の公式本文で確認できればよいこと
- R-11：資格・疾病・障害程度等を推定しない一方、推定禁止を理由に関連制度の探索を止めないこと
- 出力直前の最終確認にR-9～R-11の再点検が含まれること

読者分岐の規則は `expectedBranch()` にあります：
職員向け＝入力担当者が「クリニック職員」または使い方が「クリニック職員がAIチャットで候補を調べたい」、
本人向け＝職員向けでなく、入力担当者が「患者本人」。

## 限界

jsdom は実ブラウザではありません。レイアウト、実際のクリップボード権限、印刷ダイアログ、
ブラウザごとの差は検査できません。公開前にはブラウザでの手動確認も行ってください。
